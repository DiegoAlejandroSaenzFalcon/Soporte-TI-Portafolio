## 1. GitHub en tres frases

1. **GitHub es una biblioteca digital en internet** para guardar proyectos y documentos.
2. Un **repositorio** (repo) es un proyecto completo: su carpeta con todos los archivos y todo su historial.
3. Este repositorio tuyo (`Soporte-TI-Portafolio`) es YA un portafolio público profesional — lo que estás viendo y estudiando.

**Analogía** (la misma familia de analogías de toda la guía): un repositorio es una **caja fuerte transparente**: todos ven el contenido, pero nadie puede cambiar nada sin permiso y cada cambio queda registrado con fecha y autor.

## 2. Nube vs local (dónde vive la información)

| | En la nube (GitHub) | En tu PC (local) |
|--|---------------------|------------------|
| Dónde | Servidores de GitHub en internet | Tu disco duro |
| Para qué | Publicar, compartir, estudiar desde cualquier equipo | Trabajar sin internet, editar con libertad |
| Copia de respaldo | GitHub guarda todo el historial | Tu PC tiene una copia descargable (ZIP) |
| Riesgo | Depende de internet | Puedes perderlo si el disco falla (¡regla 3-2-1!) |

**Conclusión profesional**: los dos mundos se complementan. La buena práctica: lo importante vive en GitHub (nube) y en tu PC (local) — dos copias del mismo proyecto.

## 3. Público vs privado (una decisión de estrategia)

| | Público | Privado |
|--|---------|---------|
| Quién lo ve | Todo el mundo (sin cuenta) | Solo tú y a quien invites |
| Para qué sirve | Portafolio, demostrar trabajo, proyectos de aprendizaje | Trabajo con datos sensibles, proyectos en desarrollo |
| Costo | Gratis | Gratis (en cuentas personales) |
| Ejemplo | Este repositorio (tu guía de estudio) | Un proyecto de cliente, tu futuro "Soluciona" en fases tempranas |

**Regla antes de publicar cualquier cosa**: *"¿me sentiría orgulloso de que un reclutador vea esto?"* — para eso sirve el modo público de este repositorio. Los datos personales y contraseñas JAMÁS van a un repo público (lo veremos en el módulo 5).

## 4. El README: la portada que se ve solita

Casi todo repositorio tiene un archivo llamado `README.md`. Es **la portada**: GitHub lo muestra **renderizado** (formateado) en la parte inferior de la lista de archivos — sin que nadie tenga que "abrirlo". Por eso, al entrar a este repositorio, lo primero que lees es el mapa de la guía.

**Curiosidad técnica no escocesa**: la extensión `.md` = **Markdown**, un lenguaje de texto plano que GitHub convierte en formato bonito (títulos, tablas, imágenes, casillas `- [ ]`). Escribir en Markdown es un superpoder de documentador: es lo que está escrito en TODOS los módulos de este repositorio.
